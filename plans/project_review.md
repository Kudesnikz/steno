# Ревью проекта Steno и рекомендации по улучшению

## 1. Зависимости (Менеджмент пакетов)
**Текущее состояние:**
- В проекте отсутствует единый файл для управления зависимостями (`requirements.txt`, `Pipfile` или `pyproject.toml`).
- В `build_arch.sh` жестко зашит список `REQUIRED_PY_PACKAGES="rumps google-genai certifi py2app pyobjc-core pyobjc-framework-Cocoa pyobjc-framework-AVFoundation pyobjc-framework-Quartz pyobjc-framework-ApplicationServices"`.
- В `README.md` указан другой список: `PyQt6 google-genai pyobjc certifi py2app qtawesome markdown qdarktheme sounddevice numpy`.
- Библиотека `rumps` указана в скрипте сборки, но в самом проекте не используется (Tray-иконка реализована через нативный `AppKit.NSStatusBar` или `QSystemTrayIcon`).
- Библиотека `qdarktheme` указана в `README.md`, но в `app.py` она закомментирована и не используется.

**Рекомендации:**
- Создать единый `requirements.txt` (или `requirements-dev.txt` для сборки).
- Удалить `rumps` и `qdarktheme` из списков установки.
- Обновить скрипт `build_arch.sh` так, чтобы он устанавливал зависимости из `requirements.txt` (`pip install -r requirements.txt`).

## 2. Структура проекта
**Текущее состояние:**
- Базовый модуль записи `recorder.py` лежит в корне проекта.
- В корневой директории лежат bash-скрипты `build_arch.sh` и `build_dmg.sh`. Судя по открытым вкладкам в редакторе (`scripts/build_dmg.sh`), планировался перенос скриптов в отдельную папку `scripts/`, но это не было завершено.
- Версия приложения (0.2.0) жестко зашита в `setup.py`.

**Рекомендации:**
- Переместить `recorder.py` в `app/core/recorder.py` — это бизнес-логика, которой место внутри модуля `app`.
- Создать директорию `scripts/` и перенести туда все скрипты сборки (`build_arch.sh`, `build_dmg.sh`, добавить `clean.sh`).
- Создать `Makefile` в корне для удобного запуска сборки и очистки (например, `make build`, `make clean`).
- Создать файл `app/__version__.py` (с `__version__ = "0.2.0"`), и читать эту переменную в `setup.py` и основном приложении, чтобы версия была определена в одном месте.

## 3. Скрипты сборки и `setup.py`
**Текущее состояние:**
- В `setup.py` хардкодятся списки фреймворков и пакетов. Версия указана явно.
- Скрипт `build_arch.sh` использует команду `arch -x86_64 /usr/bin/python3 -m venv` для сборки под розетту. Использование системного Python в новых macOS (начиная с macOS 13/14) может сопровождаться трудностями из-за PEP-668 (externally managed environment).

**Рекомендации:**
- В `setup.py` читать версию из `app/__version__.py`.
- Отредактировать логику `build_arch.sh`: использовать текущее виртуальное окружение, если оно активно, или более надежно подхватывать Python. 
- Передать путь к `bin/ffmpeg` и `assets` через универсальные пути `os.path.join(BASE_DIR, ...)` в `setup.py`.

## 4. Архитектура кода (app.py)
**Текущее состояние:**
- `app.py` представляет собой монолитный файл (~500 строк), который отвечает за:
  1. Запуск приложения.
  2. Проверку системных разрешений macOS (класс `PermissionManager`).
  3. Инициализацию Tray-меню и логику взаимодействия с `AppKit`/`PyQt6`.
  4. Оркестрацию записи (запуск/остановка `ScreenRecorder`).

**Рекомендации:**
- Провести рефакторинг `app.py`, разбив его на модули:
  - `app/core/permissions.py` — вынести `PermissionManager`.
  - `app/ui/tray.py` — вынести логику работы с треем (особенно `MacTrayHelper` и `AppKit`).
  - `main.py` в корне — оставить как простую точку входа, которая инициализирует зависимости и запускает приложение.
